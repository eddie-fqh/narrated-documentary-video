# 动画：逐帧确定的 HTML / three.js

每期至少两段专属动画，讲照片讲不清的东西：结构怎么搭的、有多大、过程怎么发生、几个对象怎么比。

## 1. 页面约定

动画是一个 HTML 页面，用无头浏览器逐帧截图成 mp4。**不录屏、不依赖实时播放**，第 i 帧就是 `renderAt(i/fps)` 的截图，所以不掉帧、可复现、可以只重渲某一段。

```js
window.renderAt = function (t) { /* 只依赖 t 画出这一帧；可返回 Promise */ };
window.ready = true;   // 资源（字体、图片、模型、瓦片）都到齐之后再设
```

- `renderAt` 必须是 t 的纯函数：不用 `Date`、`requestAnimationFrame`、未设种子的随机数。需要随机就用固定种子。
- 参数走 URL：`scene=`（一个页面多个场景）、`dur=`（秒）、`c1…cN=`（提示点，秒）。
- 画布 1920×1080。

```bash
python3 scripts/capture.py anim/page.html "scene=cut&dur=9.2&c1=1.6&c2=3.8" anim/a_cut.mp4 --frames 1,4.5,8   # 先出测试帧
python3 scripts/capture.py anim/page.html "scene=cut&dur=9.2&c1=1.6&c2=3.8" anim/a_cut.mp4                    # 再整段渲染
python3 scripts/render_anims.py <ep> anim/page.html     # 按 anim/jobs.json 批量渲染，3 路并行
```

页面要 `fetch` 本地文件（glb 模型、GeoJSON）时，`file://` 会被拦，用 `--http <根目录>` 起一个本机只读静态服务。

## 2. 时长与提示点来自配音

在镜头表生成器里：

```python
L.anim("讲到模型的那句", "cut", until="下一个镜头的锚点", cues={"c1": "标签该出现的那句", "c2": "end"})
```

- 时长 = 本镜头到下一镜头锚点的间隔 **+ 0.2 秒**。
- 提示点 = 对应短语相对动画起点的秒数。页面里用 `cue("c1", 默认值)` 取，标签和动作在口播说到的那一刻发生。

**动画必须比它所在的镜头略长。** 片段比镜头短时，渲染器会把它放慢来凑时长，放慢靠重复帧，运动中的画面每秒顿一下——看起来就是「一闪一闪、微微跳」。这个问题从成片上很难猜到原因，记住规则即可。稿子或配音改了，时长跟着变，动画要重渲。

## 3. 画风：和正片是同一部片子

动画和实拍素材之间不能出现两套视觉语言。模板的风格：

- 羊皮纸底色（`#efe6d6`）加暗角；
- **实体着色的模型**：真实的材质颜色、有光有影，不用线框；
- 圆角奶油色卡片配红色左条、墨色引线和尺寸线；
- 字体、强调色（砖红、暗金）和正片的卡片一致。

不要为了「科技感」另做一套深色底、霓虹线框、HUD 界面——放进片子里就是不搭。科技感来自模型本身的精细和镜头运动。画风是用户定的，要换先问。

## 4. 三维建模（`templates/anim/model3d.html`）

程序化建模，不依赖外部模型文件：

- **旋转体 + 剖切面**：`lathe(闭合剖面, 材质, phi0, len)`。给了 `phi0/len` 就开一个口并自动补两片剖切面，「剖开看里面」不需要布尔运算。穹顶、塔、柱、瓶、钟都是旋转体。
- **按真实尺寸建模**（单位米）。尺寸线、对比、标尺才有意义；放一个 1.75 米的小人，尺度感立刻有了。
- **细节要够**：成对的柱、窗洞、肋、檐口、采光亭。一个光溜溜的半球会显得简陋——观众对「模型太糙」很敏感。
- 相机用球坐标（方位角、仰角、距离、目标点）描述，场景里对 t 做缓动插值。
- 三维画布上面叠一层二维画布画引线、尺寸线；文字用 DOM 元素（字体渲染比画布清晰）。`proj()` 把三维点投到屏幕坐标。
- 有真扫描的 glb 就用（`glb=` 参数）；重塑模型只做整体和环绕，细节嵌实拍照片。

踩过的坑：

- **共面闪烁**：只接阴影的地面如果和模型底面、台面在同一高度，阴影会一小块一小块地闪。把平面上下错开一点。
- **截图空白**：无头浏览器软件渲染下，大量带 `shadowBlur` 的描边会让整张截图变空白。要发光效果就用不同粗细多描几遍。
- 裂缝、纹理这类「示意」要画得像：细的、暗色的、有分叉的锯齿线，加一条引线和文字说明；粗而鲜艳的色带观众看不懂是什么。
- 场景开头的朝向要和口播一致（说「正面」就从正面开始，再环绕）。

## 5. 场景怎么设计

一个场景只讲一件事，动作少而慢。对同题材高播放量视频的分镜拆解里，反复出现、效果最好的几招：

- **沿中轴下降**：镜头从顶部沿剖面一路降到底，途中经过的每一层依次标注。适合讲「上下是怎么连起来的」。
- **同机位替换**：机位不动，旧方案淡出、新方案淡入。适合讲改建、多个设计方案、前后对比。
- **几何自己画出来**：平面图、比例关系由一条线从无到有画出，而不是整张图直接出现。
- **照片小窗嵌进示意图**：讲到模型的某个部位时，对应的实拍照片从那个位置弹出来。
- **尺度并排**：几个对象按真实尺寸放在同一条地面线上，数字随高度增长跳出来。
- **第一人称路线**：沿着观众实际会走的路线移动（上楼、绕行、穿过），讲「到了现场你会看到什么」。
- **开场预告**：片子开头先用 3–4 秒展示全片最好看的那段动画，再回头讲。

## 6. 现成模板（`templates/anim/`）

| 模板 | 用途 | 主要参数 |
|---|---|---|
| `model3d.html` | 三维模型环绕、剖开、量尺寸；复制后换成自己的对象 | `scene dur c1…` |
| `timeline.html` | 整屏年表，事件依次点亮 | `ev=年份:事件;… focus span` |
| `heights.html` | 高度对比（人、雕像、塔、柱状） | `items=名:米:类型:副标题;… title unit` |
| `spotlight.html` | 一幅画上依次推近并点亮几个局部 | `img regions=x,y,w,h,标题,副标题;…` |
| `filmstrip.html` | 胶卷连环画：几幅一组停住看，组间快拉 | `imgs group title credit` |
| `geomap.html` | 真实地形上的飞越、路线、地点标注 | 见 aerial-and-maps.md |

复制一个最接近的模板改成本期需要的示意图，比从零写快。只要页面暴露 `renderAt(t)` 就能截图。

**多图横向展示不要匀速滚动。** 30 帧下，细节多的画面匀速横移会糊、会跳，观众一幅也看不清。改成「一组停 3 秒 → 0.7 秒拉到下一组 → 再停」。

## 7. 先看再渲

- 整段渲染前先出首、中、尾三张测试帧（`--frames`），看构图、标签有没有压到模型、有没有错字和黑边。
- 渲染后抽看成片里动画镜头的衔接：进出的淡入淡出、和前后镜头的色调。
- 截图很吃 CPU，全机并行不超过 3 路；一段 10 秒的三维动画约 1 分钟。

## 8. 用户说「不够好看」时：拆参考片

不要凭感觉加特效。先看同题材里做得好的片子是怎么做的：

1. 搜 10 个左右同题材的高播放量视频（中英文都搜），**在平台上在线观看**，不下载。
2. 并行分析（每个视频一个分析者）：边看边逐镜头记录时长、景别、运镜方式、转场、动画讲了什么、开头前 15 秒怎么抓人。只记文字笔记，不截取、不保存对方的画面。
3. 汇总出反复出现的手法，挑和本片风格相容的借鉴——借的是「怎么讲清楚」，不是照搬画面。
4. 别人的片子只是学习对象，任何画面都不进自己的素材库。

第 5 节的清单就是这么来的。
