# 运行：并行、排队、长任务、清理、密钥

## 1. 什么可以并行

一期之内：配音（合成 + 验收）在跑的时候，同时找素材、建动画模型、做封面。配音对齐完成后才能定镜头时间。

多期之间：写稿、找素材可以放开并行；吃 CPU 的三类任务要全机限流，否则互相拖慢、内存打满：

| 任务 | 全机并发 |
|---|---|
| 渲染（render + finish） | 2 |
| 动画逐帧截图 | 3 |
| 配音合成 | 4–6 |

```bash
bash scripts/glock.sh render 2 bash scripts/render_ep.sh <ep>      # 先来先得，自动排队
bash scripts/glock.sh anim 3 python3 scripts/capture.py …
```

`glock.sh` 是一个文件系统信号量：排队号牌带时间戳，槽位用 `mkdir` 原子抢占，死进程的槽位按 pid 回收。不要用「`pgrep` 等别的任务结束」来排队——等待循环自己的命令行也会被匹配上，几个等待者会互相死锁。

## 2. 长任务

- **脱离调用方的进程树**。后台任务常有时长上限，超时会沿进程树杀掉所有后代——排了很久的队、渲染到一半的 ffmpeg 一起没了。只开新会话（setsid）不够，要让任务被 init 收养：子 shell 里起后台进程后子 shell 立即退出。

  ```bash
  ( nohup sh -c 'bash scripts/glock.sh render 2 bash scripts/render_ep.sh <ep>; echo PIPE_DONE' > work/pipe.log 2>&1 < /dev/null & )
  ```
  然后轮询日志里的完成标记，而不是等那个进程。

- **等待要等「完成标记」**，不是等文件出现。看到 `final.mp4` 就去拷，会拿到半截文件。
- 监控要覆盖失败：只匹配成功标记的监控，在任务崩溃时是沉默的，而沉默看起来和「还在跑」一样。同时匹配错误、异常退出。
- 会话重启后，之前起的子任务可能全死了，还可能留下陈旧的锁。恢复工作前先查实际状态（进程在不在、文件时间、日志末尾），不要假设它们还在跑。
- **不要改正在运行的 shell 脚本**。shell 是边读边执行的，原地修改会让正在跑的实例读到错位的内容。写新文件再改名覆盖。
- 排队等待的时间不是任务本身的耗时；估时和汇报时分开说。

## 3. 把任务分给子代理

批量做多期时，每个子代理负责几期，从装稿做到上架审片。任务书要写清楚：

- 红线（错图、水印、隐私、不许发布、不许改别人的期、不许动共用的管线代码）。
- 每一步的命令和「怎么算完成」。
- 每一步产出都要自己看图确认，不盲写。
- 汇报格式：每期一行（时长、镜头数、素材数、拿不准的地方），不贴大段内容。

子代理交回来的结论要抽查——它会把没验证的说成验证过的。事实核查、读音核对这类，让它列出「没能确认的项」。

## 4. 磁盘

- 视频项目吃磁盘很快：候选图池、淘汰素材、中间片、4K 母带。
- **测试产生的垃圾，在创建它的那个脚本里当场清理**，别留到以后再「找回来删」。
- 批量删除三条规矩：
  1. **集合先冻结**：把要删的对象列成一份固定清单落盘，而不是「发一条模式匹配让它决定删什么」。
  2. **判断在本地**：用可测试的规则（路径、后缀、大小）判定，规则先拿真实数据跑一遍看有没有误伤。
  3. **走可逆路径**：回收站、改名、移走；真要永久删，先让用户看清单。
- 正在渲染的期，它的 `work/` 不要动。

## 5. 密钥与隐私

- 密钥放在 `~/.config/<服务>/env`（权限 600），由脚本读环境变量；**不写进仓库、命令行参数、日志、文档、对话**。
- 用请求头传密钥，不放进 URL。
- 查密钥有没有泄漏到别处时，按「值」搜，不按变量名搜。
- 登录态文件（浏览器会话、cookie）等同于密钥。
- 推送到公开仓库之前：
  ```bash
  bash scripts/scan_secrets.sh <目录>
  ```
  查密钥格式、写死的凭据、长十六进制串（key、音色 ID、会话 ID）、邮箱、家目录路径、内网地址、媒体文件。命中的逐条看。素材、成片、音频不进仓库（体积和版权都不合适）。
- 提交用的邮箱如果不想公开，用代码托管平台提供的 noreply 地址。

## 6. 外部服务

- 被限流（429）就退避；连续被拒说明请求太密或被封，停下来等，不要加并发。
- 浏览器自动化反复失败两三次就停，换路或者告诉用户，不要原地重试。
- 一个操作在不该失败的地方失败了（权限不足、找不到对象），先怀疑「是不是对象搞错了」，再考虑重试。
