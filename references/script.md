# 写稿：先查证，再写成「听」的稿子

观众是听视频的。信息再对、画面再好，匀速宣布式的稿子留不住人。这一步决定全片的上限。

## 1. 查证

- 先把题材读透：对象是什么、谁做的、为什么做、怎么做成的、后来经历了什么、今天看得到什么细节。
- **每一条要写进稿子的事实都查到出处**：年份、数字、人名、尺寸、引文。记在 `factcheck.md`，一条事实一行，后面跟来源链接。
- 拿不准的不写；确实想讲的传说，在稿子里明说「据说」「传说」。
- 引文要查原话。常见的流传版本很多是后人改写的。
- 比较类的数字（谁更高、谁更宽）把几方的数字都查出来再下结论，并且口径一致（内径对内径，含不含基座）。
- 画面上的说明文字、卡片、图注也算事实，一样要核对。

## 2. 结构

1. **钩子**：一两句反常识或悬念，以一个问句收尾。开场 5 秒内让人想知道答案。
2. **固定开场白**：系列自己的一句话（写进 `series.json` 的 `opening`）。
3. **点题**：这一期讲什么。
4. **三到四章**：每章用一个问题带入，讲一件事。章与章之间用明确的口头路标（「先说……」「好，再说……」），配音时章节前会多留停顿，画面上是章节卡。
5. **实用段**（可选）：如果观众会去现场或会动手做，给几条提前查好的要点，用通用说法，容易变的信息写「以官方为准」。
6. **收束**：落回对象本身——它今天的样子、到现场看什么、它身上看得见的东西。
7. **固定结尾**：系列自己的一句话（`series.json` 的 `closing_regex`）。

长度：7–10 分钟的片子，口播 3000–3400 字。稿子太短会逼着画面切得太快。

## 3. 叙述姿态：探求，不灌输

对陌生题材，直接宣布答案没人有兴趣。把观众放到和你一样「还不知道」的位置，再把事实当成发现说出来。

- **过程句**：「我原来以为……后来一查……你想，是不是……」。一期用三到五次，不要每段都用。
- **设问**：每章开头一个问题，关键结论前先问一句。
- **短句，一句一个意思**。关键数字单独成句（「九米宽。」），前后留气口。
- **不写口头语**：「这个」「我觉得」「就是说」「哎呀」由 TTS 念出来很假。

量化基准（来自对一位以聊天感著称的谈话节目主持人 10 期节目的转写分析，用来校准，不是指标）：

| | 基准 | 念稿腔的典型值 |
|---|---|---|
| 语速 | 4.4 字/秒（四分位 3.8–5.0） | 5.7 |
| 自己两句话之间的停顿 | 中位 1.8 秒 | 0.4 秒 |
| 设问、反问 | 每百字 2 个 | 每百字 0.1 个 |
| 句长 | 句子中位 18 字，分句 8 字 | 差不多 |

「像在念」主要来自停顿太短和没有问句，而不是句子太长。语速和停顿在配音层解决（见 voice.md），稿子负责问句和节奏。

## 4. 为 TTS 写

- 标点只用「，。？」，少量「：」。不用引号、括号、破折号、省略号——念不出来，还会打乱停顿。
- 不写英文。外文人名地名一律音译，否则会被吞掉或乱读。
- 数字写汉字。年份逐字读（一五零四年）；三位数的年份逐字读有歧义，写成「五百二十三年」。
- 带小数的量写成口语读法，并在 `numbers.json` 里登记显示写法：`[["五米一七", "5.17米"]]`。字幕据此显示阿拉伯数字，配音验收据此检查数字有没有念全。
- 多音字、容易读错的专名先不改稿子，配音时用 `tts_subs.json` 替换送去合成的文字（见 voice.md）。

## 5. 逻辑要经得起听

读稿和听稿不一样，下面两类问题只有念出来才暴露，写完自己出声读一遍。

- **前后句要接得上。** 刚引了一句关于甲的话，下一句就该拿甲来比；跳去比乙，听的人会觉得断了。要比乙，先把甲交代完，再说「就连乙……」。
- **问句的答案不能是同义反复。** 「雕的是哪一刻？就是那一刻」听起来很怪。答案要给出新信息：「是手刚刚碰到她的那一刻。不是之前，也不是之后。」
- 指代要明确。连续出现两个「他」「它」而指的不是同一个，听的人分不清；该重复名字就重复，地名、建筑名用全称。

## 6. 不要的东西

- **说教式结尾**：「所以，下次当你……先别急着……停下来，想一想……」这类人生感悟。结尾落回对象本身。
- **隐私**：行程、日期、住处、同行的人、「我们今天去」「我们周三去」。「我站在它底下」这种现场感可以写。
- 没查证的新事实。改稿时尤其容易顺手加一句——不加。

## 7. 改稿：只改该改的

镜头表是按稿里的原句定位的，改得越多返工越多。

- 改已有镜头表的稿子时，改动的句子控制在三成以内，其余逐字保留；改完用 `lint_script.py --shots shots_src.json` 看锚点存活率，低于七成就把不必要的改动还原。
- 改一两句话不需要整期重配：只重做那一段的配音（voice.md「局部重配」）。
- `timeline.json`、`numbers.json`、`music.json`、`ambience.json` 里的触发文字要和稿子同步改。

## 8. 随稿子一起产出

| 文件 | 内容 |
|---|---|
| `factcheck.md` | 每条事实和出处 |
| `queries.json` | 25–35 个英文图片检索词，覆盖稿里讲到的每个具体对象。要具体到「哪件作品的哪个局部」，而不是「某城市的喷泉」 |
| `numbers.json` | `[["汉字读法", "显示写法"], …]` |
| `timeline.json` | 顶部时间线：`[[年份, "四字左右的标签", "稿中触发子串"], …]`，4–8 个，按口播出现顺序且年份递增（倒叙提到的年份不放）；公元前写成字符串 `"前44"` |

## 9. 检查

```bash
python3 scripts/lint_script.py script.txt --series series.json --shots shots_src.json
```

报英文、阿拉伯数字、不能念的标点、说教句式、口头语、行程和日期，并打印字数、句长中位数、设问密度、锚点存活率。场馆常识类的误报（如「周一闭馆」）自己判断。
