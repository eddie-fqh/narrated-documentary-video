# 配音：合成、验收、停顿、对齐

## 1. 选声音

- 推荐克隆自己的声音，用 Fish Audio 或 ElevenLabs；注册、克隆、密钥配置和接口用法见 [voice-cloning.md](voice-cloning.md)。
- 用耳朵选，不看参数表。同一段话让几个模型各念一遍，听哪个像人在讲。
- 定下来的音色、参考音频、模型版本是**不变量**。省钱、提速的方案都不能碰它们；也不要事后调音高。一个系列换了声音，观众立刻听得出。
- 语速在合成参数里设（约 0.95 倍），不要合成后变速。**语速要对所有生成步骤生效**，包括后面每一次重掷——只在首次生成时传语速，重掷的段会比邻段快 5% 左右，开头钩子段甚至快 20%。

## 2. 分段合成

`scripts/tts_segments.py` 和具体的 TTS 服务无关，用 `TTS_CMD` 模板对每段调用一次：

```bash
export EP_DIR=<ep>
export TTS_CMD='my-tts --voice <音色> --speed 0.95 --in {text_file} --out {out}'
# 用 Fish Audio / ElevenLabs 的克隆音色：
#   export TTS_OUT_EXT=mp3 TTS_CMD='python3 scripts/tts_cloud.py fish --speed 0.95 --in {text_file} --out {out}'
python3 scripts/tts_segments.py          # 文字没变的段自动复用
```

- 每段约 180 字（`SEG_MAX_CHARS`），在句末断开。段太长，模型容易在后半段飘或截断。
- 末段太短会并回上一段：孤立的几十字结束语语气和音色最容易偏。
- 每段量积分响度后做线性增益拉到 −17 LUFS，再拼成成品。
- 清单 `audio/segments/manifest.json` 记录每段的文字、文件和时长。**真实时间轴 = 各段文件时长累加**，不要相信任何「估算的」起止时间。
- 密钥由 `TTS_CMD` 里的程序自己从环境变量或权限 600 的 env 文件读，不要写进命令行。

## 3. 验收：两层闸门加一个人

**声学层**（需要音色参考；按你用的 TTS 配套实现）——这些指标全过，只说明「声音没坏」：

| 检查 | 判据 |
|---|---|
| 循环/重复 | 转写里出现原文没有的重复片段 |
| 音色相似度 | 低于参考分布的第 5 百分位 |
| 音高 | 段平均基频偏离参考超过 ±100 音分 |
| 相邻段音高 | 相邻两段跳变超过 ±120 音分 |
| 响度 | 整条 −17±1 LUFS，段间极差 ≤2.5 LU |

**内容层**（`scripts/check_segments.py`，用 whisper.cpp 转写）——专抓声学正常但念错的：

| 检查 | 判据 |
|---|---|
| 口头语 | 带口语提示转写，出现原文没有的「呃、嗯、啊」 |
| 截断 | 语速超过 7 字/秒，说明后半段没念出来 |
| 数字 | `numbers.json` 里的数字在转写里找不到，或数字发音短于 0.55 秒（吞音） |

```bash
python3 scripts/check_segments.py --reroll 3     # 不合格的段自动重掷，最多 3 轮
```

**人**：读错的字、多音字、别扭的重音，机器指标都抓不到——发音错误不是声学异常。成片必须有人听过一遍。听出问题时记下时间点和那句话，按第 5 节局部重配。

## 4. 段不过怎么办

按这个顺序，前一招不行再用后一招：

1. **重掷**（同样的文字再合成一次）。对口头语、吞字、截断有效。
2. **重切分**。音色相似度卡住时，重掷基本无效，换一个分段长度（150–240 之间）让边界落在别处，通常就过了。
3. **改写**。同一个数字连掷三次都报找不到，多半是读法有歧义：把稿子改成更口语的读法，同步改 `numbers.json` 和别处引用的文字。

注意：

- 数字闸门会误报。「2 米 02」和「2.02 米」、「4 成」和「40%」这类一数多写，转写和登记的写法对不上就报错。先看转写到底是什么，补 `numbers.json` 或放行。**白掷会把音高越掷越偏。**
- 重掷循环「掷满次数」不等于通过；自动循环的结尾要看日志里有没有仍未过的段。
- 同音字（他/她）自动转写分不出来，不要拿它做自动循环的通过条件——人听一下就定了。
- 转写用的模型偶尔单遍会漏听某个专名；有疑问时换一个转写模型复核。

## 5. 读音修正

`<ep>/tts_subs.json` 只改**送去合成**的文字，稿子、字幕、锚点保留原字：

```json
{"伽": "加", "晃眼": "谎眼"}
```

- 多音字：换成同音的单音字。
- 人名里的间隔号「·」有的模型会念成一个多余的音节：送合成前去掉（`TTS_STRIP_CHARS`，默认已去）。
- 同一个专名在全片的读音要统一——改一处就把含这个词的段都重做。

## 6. 局部重配（改一两句话）

不要为一句话整期重做，也不要重跑整条配音流程。

1. 改 `script.txt` 里那句话。只要没影响分段边界，`tts_segments.py` 只会重新生成文字变了的那一段。
2. `python3 scripts/tts_segments.py`（或 `--only 6` 指定段号重掷）。
3. 看新段的字/秒和前后段是否接近；转写一遍，确认没有吞掉半句。
4. `python3 scripts/pace.py`——只在刚拼好的成品上跑一次。
5. `align.py` 重新对齐，然后整期重渲（画面时间跟着变）。

成品里一个很短的杂音（爆音、多出来的半个字），不值得重配：在那一小段时间窗里做衰减即可，分段文件和成品都要处理，处理前留备份。

## 7. 停顿

`scripts/pace.py` 在段与段之间插入真实停顿：普通段间 0.6 秒，章节开头前 1.2 秒（段首匹配 `PACE_CHAPTER_PREFIXES` 里的路标词）。停顿用极低电平的粉噪而不是数字静音，避免拼接处的咔嗒感。它写 `gaps.json`，对齐时据此修正各段起点。

停顿只能插一次：成品已经插过就会拒绝再跑；任何重拼都要再走一遍 pace → align。

## 8. 逐字对齐

多数 TTS 不给时间戳。`scripts/align.py` 用 openai-whisper 的逐词时间，加序列比对，把时间映射回原稿的每一个字，写 `work/chars.json`。后面所有锚点都查这张表。

- 每段换几种提示词各转写一遍，取匹配率最高的。**用原稿开头当提示词会让模型跳过开头**，匹配率能掉到两成。
- whisper.cpp 快 20 倍，适合验收转写；但它的词级时间在每个转写片段开头会挤在一起，用来切镜头会错。对齐仍用 openai-whisper。
- 没匹配上的字按前后已知时间线性插值。匹配率低于九成的段，回头检查那一段是不是念错了。

## 9. 并发

合成 4–6 路并发即可。配音验收和对齐吃 CPU，和渲染、动画截图抢资源时会明显变慢，用 `scripts/glock.sh` 统一排队（见 ops.md）。
